# Jev 模擬検品ライン

ルートの `inspection.cmd` をダブルクリックし「検品開始」。起動だけではAPIを呼びません。
寸法・重量・傷の長さ・色差・ラベルの検査値を与える模擬ラインです。画像認識や実機制御ではありません。
画面の傷マークは測定値の説明用で、Jevが画像を見て検出したものではありません。

- 24個の製品を生成。投入間隔は開始前に1.2秒／0.4秒を選択できます。
- Jev比較とAPIなしの固定ルール実演を切り替えられます。
- 同じ製品列を繰り返せます。別の列は `inspection.cmd --seed 12`。
- 一時停止はラインの時計を止めます。通信中のAPIは完了するため、速度比較は停止せず実行してください。
- 取得から4秒のライン時間で仕分け。未回答・エラーは要確認へ送り、遅い回答で仕分け結果を書き換えません。
- APIは同時1件。認証・利用制限などの致命的エラー後は送信を停止し、未判定品を要確認に送ります。

## 基準

幅49.5〜50.5mm、重量97〜103g。傷は標準品1.0mm以下、高品質品0.3mm以下。
色差は標準品4以下、高品質品2以下。ラベル正常が必須。境界値は合格です。
既知の違反が一つでもあれば不良、それ以外で欠測があれば要確認、残りは良品。
欠測と既知の違反が同居するケースは不良を優先します。

モデルには当該製品の規格・測定値・判断規則だけを渡します。
生成時のケース名・正解・固定ルールの出力は渡しません。
正解は模擬ケース作成時に付けた規格上の分類です。現実の製品不良に対する検出性能を示すものではありません。
固定ルールにも同じ測定値・規格を渡します。規則を明示した課題のため、固定ルールが強いことを前提にしています。

## 指標・ログ

基準との一致数、不良を良品とする見逃し、良品を不良とする誤排除、要確認数、API往復時間を表示します。
要確認は見逃しに数えませんが、三分類での基準との不一致には数えます。
比較欄は仕分けゲートまで到達した製品だけが対象です。固定ルールは通信待ちを付けず即時計算します。
平均API往復時間はキュー待ちを含みません。ログには製品投入・回答到着のライン時刻も含みます。

ローカルの `runs/inspection-日時/results.json` に測定値、正解、実際の送信内容、応答、最終仕分けを保存。
モデルは `jev-preview`。応答に含まれる実モデルIDも記録します。
閉じると途中経過を保存します。仕分け前の製品は集計対象外です。

`inspection.cmd --smoke` は12個の模擬データを実APIで確認し、`runs/inspection-smoke-日時/` に保存します。
通常の単体テストはAPIを呼びません。検品のみの依存は `requirements/inspection.txt`。

## 初回の動作確認

2026-09-22、seed=7の12個を逐次APIに送信し、12個すべて規格上の分類と一致しました。
往復は約0.5〜0.7秒。これは小規模な動作確認で、ラインの期限内処理率や実製品の不良検出性能の検証ではありません。
