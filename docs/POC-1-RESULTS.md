# PoC 1: Jevによる直接操舵 — 1回のプロンプト調整

2026-09-22。HighwayEnv 1.12.1、jev-latest、seed=7。
それぞれ12秒、中央車線から右0.65m・右向き0.03radで開始。
物理更新30Hz、要求開始間隔最短0.25秒、同時API要求1件。

## 変更したもの

`pocs/driving/app.py` の質問文と選択肢の説明のみを調整した。入力の数値構造、物理、操作の数値変換は同じ。
併せて回答ごとのconfidenceと確率分布をログに保存するようにした。

- `held_*` は現在までの古い操作であり、次の操作の推奨ではないと明記。
- 操舵の目標を「中央車線 y=4、車体の向き0」に固定。追い越しをしない。
- 中央に到達する前に車体の向きを戻す、切り返しの例を追加。
- 自車線の前車と隣車線を区別し、負の接近速度は離れていくことを明記。
- 低速で前方に余裕があれば正の加速度を選ぶ例を追加。
- 数値だけだった操作選択肢に、用途を説明する文章を付けた。

これは純粋な言い換えだけではなく、運転目標を絞った調整でもある。
自動操舵補正、モデル回答の上書き、PID、追加の制御ルールは導入していない。

速度・横ずれはAPI要求時点の観測値であり、全物理フレームの極値ではない。
両方とも終了時の通信中1件は適用せずに記録した。
同じseedだが通信遅延と選択された操作が違うので、走行軌跡・他車の反応も異なる。
各条件1回のみ。性能保証や統計的に確立した改善ではない。

## 結論

停止近くまでの過剰減速は今回の走行では解消した。
ただし左右の切り返しが多く、車線中央の維持には失敗する場面が残る。
APIの速さは確認できたが、連続的な操舵を安定させる能力とは分けて評価すべき。
このPoCではこれ以上チューニングせず、次の題材を検討する。
