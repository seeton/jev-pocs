# 実画像の検品PoC

`vision.cmd` をダブルクリック。追加の画像APIキーやGPUは不要です。
初回はMVTec ADのボトル画像の一部をダウンロードし、正常画像から基準を作ります。
「前へ／次へ」「自動再生」「正解を表示」で確認できます。
画像の解析は常にローカルで実行。「Jevで仕分け（API）」を押した画像だけ、数値特徴を既存のJevキーで送ります。

## データと利用条件

- 原著者・提供元：[MVTec Software GmbH, MVTec AD](https://www.mvtec.com/research-teaching/datasets/mvtec-ad)
- データライセンス：**CC BY-NC-SA 4.0（非商用）**。
- ダウンロード元：[Hugging Faceのfoersben/mvtec-adミラー](https://huggingface.co/datasets/foersben/mvtec-ad)
- リビジョン：`c75b39616f84db43677bcc8228caaafaf5096d7f` に固定。
- `data/mvtec-bottle/` に画像・マスク・元のライセンス・ファイルハッシュを保存します。約39MB。
- データと派生画像はGit管理対象外。リポジトリには画像を再配布しません。

## 何を認識するか

深層学習や画像LLMではなく、**正常画像を参照する軽量な統計的異常検知**です。
128×128に縮小し、4×4画素ごとにRGB平均・標準偏差・輝度勾配を計算します。
正常画像の同じ位置と隣接位置に近い特徴がなければ、異常度が上がります。
傷・欠け・汚れの種類を意味的に識別する機能はありません。撮影位置や照明の変化にも影響されます。

- 学習：`train/good/000〜029` の正常30枚。
- 閾値校正：`train/good/030〜039` の別の正常10枚。
- 評価：`test` の良品・大きな欠け・小さな欠け・汚染、それぞれ000〜007の8枚、合計32枚。
- テスト画像と正解マスクは、学習と閾値選定には使用しません。
- 画像スコアは異常度上位11パッチの平均。画像閾値は校正画像の最大スコア×1.1。
- 赤い候補領域は校正パッチ異常度の99.5パーセンタイル超過箇所です。

画面の元写真は実画像です。中央の赤い表示が検出結果、右の緑がデータセットの正解です。
緑のマスクは評価・表示だけに使い、画像検知器にもJevにも入力しません。

## Jevの役割

`jev-preview` に異常度、閾値との比、異常パッチ割合を渡します。
比が0.8未満なら良品、1.2超なら不良、その間は要確認という方針を適用させます。
画像・ファイル名・正解ラベル・正解マスク・ローカル判定結果は送信しません。
Jevは画像を見ておらず、この段階ではローカル検知の誤りを修正できません。
画像検知の精度と、Jevが与えた仕分け方針に従えたかは別の評価です。

## 初回評価

2026-09-22、固定した上記32枚で画像AUROC **0.9479**。
閾値比1.0で二値判定した場合、不良24枚の見逃し0、良品8枚の誤排除3。
UIの三分類では要確認10枚。二値集計と三分類の数字は別です。
不良画像の領域IoU平均は **0.2982**（32×32に縮小したマスク上）。位置の検出は粗い結果です。
画像処理は平均約54ms（読み込み・特徴抽出込み）。学習とAPIの時間は含みません。
少数かつ固定されたボトルの部分集合であり、全MVTecや実工場での性能を示す結果ではありません。

```powershell
# ローカル画像評価のみ：Jev APIなし
.\vision.cmd --evaluate
# 32枚を画像評価し、最初の4枚の特徴をJevにも送る
.\vision.cmd --smoke
```

評価と実際のJev入力・応答は `runs/vision-日時/evaluation.json` に保存します。
依存：`requirements/vision.txt`。通常の単体テストはダウンロードもAPI通信も行いません。
